Car plan

Car capacity is separate from pod berths. Each itinerary owns one car and one whole party.

Supply all times in integer seconds. Zero means an authored zero duration. Shared consent applies to both pod legs.

Car lots

Itineraries

A full lot refuses the itinerary. Outward queue refusal uses drive-home. Return refusal uses retain-car and leaves the party stranded.

Energy profiles

Supply one flat-v1 profile for every fleet class. Include assumed payload in fixed mass. No physical coefficients are prefilled.

The estimate has no grade, battery, charging, or drafting model. All vehicles use auxiliary power, including idle vehicles.

Run locally

Place the exported files beside your project.json. Run these commands from the Podsim repository.

Replace HORIZON and QUEUE_LIMIT with your authored controls. The horizon must be positive and at most 24h.

go run ./cmd/parkride -project project.json -plan car-plan.json -duration HORIZON -queue-limit QUEUE_LIMIT -output car-report.json

go run ./cmd/compare -project project.json -energy-file energy.json -duration HORIZON -queue-limit QUEUE_LIMIT -format json -output energy-report.json

Compare uses its own demand and policy flags. These commands run separate models. Compare does not consume the car plan.

Use go run ./cmd/compare -h to select comparison demand and policies. Preserve the inputs and command with each report.

View a report

Import car-report.json (version 1) or energy-report.json (schema 15). Refused, stranded, and censored itineraries remain visible.

Browser limits: inputs 10 MiB, reports 32 MiB, JSON depth 32, and 300,000 values. Integers must fit JavaScript's exact range. Use the CLI for larger files.
